# WMA301 V4：实验性 Web 救援与 OEM BL33 自更新

> **测试分支，不是可刷机版本。** 对应用户提供的 fork4.zip 补丁，保留原有 WMA301 Yuzhii BL33 方案。已经通过交叉编译，但没有完成原厂 BL2/BL31 启动、新 Web UI 和 FIP 自更新实机测试。

## 新功能

- 专用中文单页 Web 界面（固件升级、内存启动、系统信息、环境、备份、UBI、串口命令控制）。
- 从 `factory_info` 分区偏移 `0x1c` 读取 MAC，通过有效单播 MAC 检查后设置 `ethaddr`。
- 实验性 `WMABL33` 固件包：先验证设备标识、SHA-256、XZ/CRC32 和解压后的链接地址；尝试只替换 OEM FIP 中的 BL33，保留原厂 BL31 数据。
- 保持原厂前 7 MiB 布局和 `0x700000` 起的 121 MiB 单 UBI；环境卷 `ubootenv` 和 `ubootenv2` 均为 124 KiB；无原厂 A/B 或 NMBM。

## 必须知道的风险

- FIP 是**唯一的启动区域**。该更新功能通过上层 MTD 设备擦写 FIP，即使成功编译和回读验证，也无法避免断电、死机、未知坏块映射或写入过程中异常造成的永久无法启动。软件“失败自动恢复”不能提供掉电回滚保障。
- Web 的 `/bl2.html` 被禁止；`/uboot.html` 只在配置了实验性自更新时存在。但高级控制台和 UBI 功能仍开放，**这不是一个无法修改引导区的安全沙箱**。
- 生成的 `DO_NOT_FLASH_WMA301_BL33_UPDATE_EXPERIMENTAL.bin` 仅供离线格式和校验测试，**不要用于实际刷写 FIP**。先完成原厂备份、实机 UART 加载、验证恢复机制、验证 FIP 重打包的真实 NAND 映射，再考虑开启该操作。
- 不应把源代码编译通过误认为原厂 BL2/BL31 已经接受新镜像，或 Web 网络已经可用。

## 后续

至少还要验证：Reset 进入 Web、MT7531 链路 / DHCP、MAC 正确读取、UBI 启动与 `saveenv`、FIP 仅读回的检查、断电及写入中断情况下的独立恢复路径。实机测试前，保持官方 NAND 和生产 U-Boot 不变。
